## Description

Chrome Version : 73.0.3683.86
OS Version: Mac OS X 10.14.2

What steps will reproduce the problem?

I noticed when using Google Chrome on Mac OS X that it performs an insecure file write to /private/tmp that could lead to a privilege escalation and/or sensitive data being compromised via a basic symlink style attack.

The file:

/private/tmp/.keystone_install_lock

A malicious user could perform a symlink attack against any file or directory belonging to the target (Chrome) user which results in the permissions being changed to to rw-rw-rw or drw-rw-rw if it's a directory.

I have uploaded a Flash video (Chrome.flv) showing a standard (non-admin) user performing the symlink attack against the target user and how I was able to view content under their directory.

It's worth noting that this exploit only works after Mac OS X has been started. The reason being is that when Mac OS X restarts it automatically clears out the /private/tmp directory. Only when the directory has been cleared out of the lock file, can the malicious user perform the symlink attack against the target user.

Please let me know if you can confirm this flaw or need further information. Thanks!

-Patrick
