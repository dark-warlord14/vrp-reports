## Description

from [b/161151868](https://issues.chromium.org/issues/161151868):

(1) The Chrome vulnerability in v8 js engine  

**VULNERABILITY DETAILS**

Type confusion in Promise.allSettled

When user calls Promise.allSettled, v8 would call following functions:  

PromiseAllSettled ---> GeneratePromiseAll ---> PerformPromiseAll

In torque function `PerformPromiseAll`, it iterates an user-provided object and calls PromiseResolve on each of item, like the pseudo-code below:

for each item in iterable:  

Promise.resolve(item).then(resolveElementFun, rejectElementFun)

`resolveElementFun` and `rejectElementFun` are generated by `createResolveElementFunctor` and `createRejectElementFunctor`, respectively. And both of them will eventually call `PromiseAllResolveElementClosure`, if user use Promise.allSettled as caller.

<https://source.chromium.org/chromium/chromium/src/+/master:v8/src/builtins/promise-all-element-closure.tq;l=155;drc=2e895c13769981d4b292731259e9f8e7a4c681af>

In function `PromiseAllResolveElementClosure`, it will read {remainingElementsCount} from {context}'s slot firstly, subtract 1, and save it back to {context}. {remainingElementsCount} represents the number of pending promise and when it becomes to zero, the function will return an array of objects that each describes the outcome of each promise.

<https://source.chromium.org/chromium/chromium/src/+/master:v8/src/builtins/promise-all-element-closure.tq;l=128;drc=2e895c13769981d4b292731259e9f8e7a4c681af>

Normally, either `resolveElementFun` or `rejectElementFun` should only be called once at most, which means turning a pending promise to fulfilled or rejected state. However, user can get `resolveElementFun` and `rejectElementFun` through some user defined js functions. Once both of them are called, {remainingElementsCount} will be substracted twice but only one promise has been processed. So the result of Promise.allSettled will be returned to user in advance. An attacker may use this vulnerability to cause type confusion, and achieve arbitrary code execution.

**REPRODUCTION CASE**

Run d8 v8\_poc.js in debug build and d8 will crash due to a torque assert:

abort: CSA\_ASSERT failed: Torque assert 'remainingElementsCount == 0' failed [src/builtins/promise-all.tq:284]

### sy...@chromium.org (2020-07-15)

The way this works in the spec is via [[AlreadyCalled]], as marja@ noted. 

In step 6.l in PerformPromiseAllSettled [1], _alreadyCalled_ is a Record { [[Value]]: false }. This Record is shared between both the resolve and reject functions via their [[AlreadyCalled]] slot. That Record is a box that holds the shared boolean value. Let's see what the right way to fix this in the Torque implementation is...

[1] https://tc39.es/ecma262/#sec-performpromiseallsettled
